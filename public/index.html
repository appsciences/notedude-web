## why

why this exists.

we wanted a place to put a thought before it disappears. fast enough for a keyboard, flexible enough for messy notes, and useful after the capture is over.

so we’re building from a small core: plain text, tags, and very little ceremony. some of the fun is already here. some is still on the drawing board.

01

write at the speed you think

Vim-style navigation, deliberate e / i editing, back/forward history, and Markdown that stays plain text. Headings, lists, code, tables, and a raw-source toggle are here.

02

a home for every client and project

Tags replace folders. Tag-pin the client’s standing brief above project notes when its first tag matches your search. Rename, merge, or remove a tag across notes without hand-editing each one.

03

notes that become next actions

to_dude ↗ is the task-focused side of the idea: capture, decide what matters today, and move the rest to near-term, long-term, or done. NoteDude already has these #tasks-* lists and keyboard moves; the dedicated to_dude build is coming soon.

04

bring your assistant

The MCP server lets an assistant work with notes. The next step is a familiar NoteDude surface inside a Claude Artifact or ChatGPT Site, so the conversation and the notes can sit together. Those embedded experiences are coming soon; the standalone app is available today.

05

mobile capture that lets you finish

coming soon Record the audio and keep the transcription. A real stop button ends the recording when you decide you’re done—pauses should never interrupt a thought. That’s the direction for our mobile voice-capture client, alongside the mobile web and share-capture work.

06

Genius tags: small label, big follow-through

coming soon · concept Tags that kick off workflows: route a captured idea, start a follow-up, or hand a note to an assistant. Ordinary tags organize your notes today; Genius tags are our idea for making them act.

## faq

good questions.

>what’s the difference between pinning and tag-pinning?

Pinning keeps a note at the top of your library. Tag-pinning makes a note rise to the top of a matching tag search when its first tag matches. Think: a client brief above that client’s project notes.

>is this Vim in a browser?

It borrows the good bits: j/k to browse, i or e to edit, and a visible INSERT mode. It isn’t a full Vim editor. Enter applies a search; Esc saves and leaves editing. Full Vi modes are still an idea in the backlog.

>can I get my notes out?

Yes. Shift+E exports all notes as a versioned JSON backup; Shift+I imports one. Keep backups somewhere you control. Markdown lives in the note text, so the source stays readable.

>did that change really save?

The app shows unsynced and failed-write states, keeps unsynced edits on the device, and warns before closing while writes remain. Check the save status before switching devices; a local pending edit is not yet a cloud backup.

>can I undo an accidental archive or delete?

In idle mode, z undoes note actions and ordinary saved text edits; Shift+Z redoes them. dd asks before permanent deletion. Recovery history is session-only, so don’t treat undo as a backup after reloading.

>will voice capture stop when I pause?

The planned mobile recorder is designed to wait for your Stop button, keep the audio, and produce a transcript. That dedicated capture experience is coming soon; it is not a recording feature in the current web app.

>what’s available now, and what’s still an idea?

Markdown rendering, task-list tags, tag-pinning, JSON backups, and the MCP server are in the codebase. Mobile recording, Genius tag workflows, and embedded assistant experiences are still planned. The workbench above links to the backlog.
